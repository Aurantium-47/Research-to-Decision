# 决策输出约定

这是工作流的验收标准，不预设用户的行业、预算或个人偏好。

| 环节 | 合格输出 |
| --- | --- |
| 需求 | 已知背景、硬条件与待确认偏好分开；只问会改变选择的问题 |
| 遗漏发现 | 从实际案例、替代路线和反证提出可能遗漏的条件，不擅自认定为用户要求 |
| 候选 | 覆盖不同可行路线；已有方案优先；不硬凑固定数量 |
| 检索 | 根据证据缺口选择来源与关键词，记录重要转向；未找到不等于不存在 |
| 功能 | 对照原文或实现，说明同一任务下的实际差异、依赖和成本 |
| 开源指标 | Star、版本、维护情况及日期；单项安装量单列；热度不能代替效果 |
| 选择 | 当前首选、最强替代项、淘汰理由、什么新条件会改选 |
| 演示 | 能改变排序时做小测；真实运行、官方样例和手写示意分开 |
| 证据 | 重要结论可回查；识别转载同源、过时信息与关键冲突 |
| 交付 | 先结论，再用足够的解释支持决定；详细证据另存，不把决定退回给用户 |

一次输出不必展示这张完整表。复杂程度随实际决策调整；信息不足时给条件分支和最值得补查的缺口。
